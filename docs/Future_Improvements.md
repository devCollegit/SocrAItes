# 🦉 SocrAItes: 추후 개선점 및 구현 방안 (Future Roadmap)

본 문서는 SocrAItes(소크라테스식 학습 코치 Agent) 시스템의 완성도와 학술적 깊이를 높이기 위해 계획된 추후 개선 방향 및 상세 구현 방안을 다룹니다.

---

## 1. RAG & 검색 엔진 고도화 (Retrieval Engine)

### 1.1 Cross-Encoder 기반 Reranker 도입
* **배경**: 현재 Elasticsearch를 통한 BM25 + Dense KNN 하이브리드 검색 및 RRF(Reciprocal Rank Fusion) 결합으로 1차 검색 결과를 얻고 있으나, 의미적 유사도 평가가 여전히 Bi-Encoder 구조에 한정되어 있습니다.
* **개선 방안**: RRF 검색 결과 상위 $N$개 청크에 대해 `BAAI/bge-reranker-large` 또는 Cohere Rerank 등 Cross-Encoder Reranker를 적용하여 질문과 강의자료 단락 간의 미세한 관계를 재정렬합니다.
* **기대 효과**: RAG 시스템의 신뢰도(Grounding Accuracy)가 향상되어 오답 또는 무관한 강의 구절 인용을 방지합니다.

### 1.2 멀티모달 RAG (Vision RAG) 확장
* **배경**: 이공계 및 대학원 강의 자료(PDF)에는 다이어그램, 시스템 아키텍처, 수식, 그래프 등 중요 시각 자료가 풍부하지만 현재 텍스트만 청킹하여 맥락이 유실됩니다.
* **개선 방안**: PDF 페이지를 이미지로 변환한 후, `ColPali` 등의 멀티모달 문서 검색 모델이나 `GPT-4o` 비전 API를 활용해 이미지 내 텍스트와 레이아웃 구조를 보존하여 인덱싱합니다.
* **기대 효과**: "이 아키텍처 그림에서 컴포넌트 A와 B의 상호작용은 무엇을 의미할까?" 같은 이미지 기반 소크라테스 문답이 가능해집니다.

### 1.3 계층적 청킹 (Parent-Child Chunking)
* **배경**: 검색 성능을 최적화하기 위해 잘게 쪼갠 하위 청크(Child)는 검색 확률은 높으나 LLM에 공급 시 거시적인 문맥이 누락됩니다.
* **개선 방안**: 300자 내외의 하위 청크로 검색을 수행하되, 매칭된 결과의 상위 1500자 내외 부모 청크(Parent)를 LLM 프롬프트에 제공하도록 데이터 파이프라인을 다원화합니다.

## 2. 소크라테스식 대화 & 에이전트 고도화 (Agent Orchestrator)

### 2.1 LLM 기반 좌절 신호(Frustration Level) 감지 정교화
* **배경**: 현재는 단순 키워드 하드코딩 매칭으로 사용자의 감정을 감지하여 한계가 존재합니다.
* **개선 방안**: 대화의 흐름과 사용자의 발화 톤을 인지적으로 평가하는 별도의 감정 분류 노드(Cognitive Load & Frustration Classifier)를 LangGraph 내 Coordinator 전단계에 배치합니다.
* **기대 효과**: 사용자가 실제로 겪는 곤경에 대해 유연하고 적절한 힌트(Scaffolding)를 적시에 제공할 수 있습니다.

### 2.2 Evaluator 피드백 루프 개선
* **배경**: Evaluator 노드가 검증 실패 시 단순히 에러 피드백을 전달하여 재생성할 때, 동일한 실수를 반복할 우려가 있습니다.
* **개선 방안**: Evaluator가 생성하는 피드백에 구체적인 대조군 예시(Contrastive Prompting, 예: "직답 노출 피하기", "힌트에 적절한 비유 사용하기")를 포함하고, 이를 Dialogue Agent 프롬프트에 동적 인자로 바인딩합니다.

### 2.3 에이전트 장기 기억(Long-Term Memory) 탑재
* **배경**: 새로운 세션이 시작되면 이전 세션에서 학생이 겪었던 개념적 공백이나 약점이 완전히 리셋되는 문제가 있습니다.
* **개선 방안**: SQLite의 `weaknesses`(약점) 및 `schedules`(복습 일정) 테이블을 기반으로, 대화 시작 시 해당 유저의 unresolved weaknesses 정보를 수집하여 에이전트의 페르소나 및 프롬프트에 주입합니다.
* **기대 효과**: "지난 대화에서 로킹(Locking) 개념을 다소 어려워하셨는데, 2단계 락킹 프로토콜에 대해 이어서 탐구해볼까요?"와 같이 진정한 1:1 맞춤형 튜터로 작용합니다.

## 3. 기능적 도구(Function Calling) 개선

### 3.1 퀴즈 중복 방지 및 어댑티브 퀴즈(Adaptive Quiz) 구현
* **배경**: 사용자가 퀴즈를 연속으로 요청 시 동일한 강의 자료 단락에서 동일한 퀴즈가 반복 출제되는 현상이 발생합니다.
* **개선 방안**: `generate_quiz` 툴 호출 시 데이터베이스의 세션 메일 로그에서 이전 출제 질문들을 파싱하고, LLM 프롬프트에 **부정적 제약 조건(Negative Constraints)**으로 주입해 완전히 새로운 문제를 출제하도록 제어합니다.

### 3.2 세션 및 유저 식별자(session_id, user_id) 연동 완전화
* **배경**: 툴 실행 주체가 LLM(LangChain Bind Tools)이다 보니 호출 시점에 API 레벨의 `session_id`와 `user_id`를 전달받지 못해 데이터 격리가 완벽하지 않습니다.
* **개선 방안**: LangGraph `state`에 `session_id` 필드를 명시적으로 바인딩하고, `diagnosis_agent` 노드 실행 시 생성된 툴 호출 인자(arguments) 객체에 `state["session_id"]`를 런타임에 동적으로 주입하여 실행합니다.

## 4. UI/UX 및 시각화 개선 (Interactive UX)

### 4.1 인터랙티브 퀴즈 전용 UI 컴포넌트
* **배경**: 대화창에서 텍스트로 오답을 기입하는 방식은 사용자 피로도를 가중시킵니다.
* **개선 방안**: `generate_quiz` 툴의 JSON 결과 데이터를 프론트엔드 단에서 파싱하여 객관식 카드로 렌더링하고, 클릭 및 터치 인터랙션으로 답안을 즉시 제출/채점하는 전용 UI를 구현합니다.

### 4.2 복습 캘린더 및 약점 시각화 대시보드
* **배경**: SQLite의 `schedules` 및 `weaknesses` 테이블에 저장된 데이터를 사용자가 유기적으로 확인할 창구가 부족합니다.
* **개선 방안**: FullCalendar 라이브러리를 임베딩하여 복습 일정을 달력 형태로 표시하고, Chart.js를 사용해 이해가 부족한 단원별 분포(Severity 분포)를 시각적인 학습 분석 대시보드로 구성합니다.

---

## 5. 정량적 평가 및 실험 자동화

* **RAGAS 기반 평가지표 자동화**: RAGAS 프레임워크를 연동하여 강의자료 답변에 대한 Faithfulness, Answer Relevance 등을 배치로 평가해 SRS 비기능 요건 충족률을 지속적으로 트래킹합니다.
* **시나리오 시뮬레이션**: 다양한 성향(적극적 학생, 수동적 학생, 쉽게 포기하는 학생)의 페르소나 봇을 구축해 SocrAItes API를 호출하여 시나리오가 올바르게 작동하는지 통합 테스트를 자동화합니다.
