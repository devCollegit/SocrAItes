## 슬라이드 2: 성능평가 A — 품질 지표

### 제목 영역

```
성능평가 A: 품질 지표 (14주차 기준)
```

### 부제

```
교수님 제공 Agentic AI 평가방법론 4축 대응
```

---

### 슬라이드 본문 구성

#### 상단 왼쪽 — 평가 방법론 설명 박스

```
평가 프레임 (14주차 AgenticAI 평가방법론)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

① Trajectory Accuracy
   - 각 입력에 대해 예상된 경로(learn/chat/tools/escape)로 
     정확히 라우팅되는지 측정
   
② τ (Consistency Probability) 
   - 동일 질문 반복 시 일관성 있는 결정을 내리는 확률
   - MAS 멀티에이전트 시스템의 핵심 지표
   
③ Tool Selection & Execution Accuracy
   - 도구 호출이 필요한 순간 정확히 tools 경로 진입
   - 호출된 도구가 정상 결과 반환
   
④ Grounding Rate (근거 기반 응답률)
   - learn 경로에서 RAG로 검색된 문서 활용률
```

#### 중앙 — 4축 성능 테이블 (핵심)

```
평가 축              점수      결과    측정 샘플  
────────────────────────────────────────────────────
Trajectory         100%     ✓ PASS   8개 케이스
Accuracy          (1.0)     모두      (라우팅별
                           정확       균형샘플)

τ Consistency      100%     ✓ PASS   3개 프롬프트
                  (1.0)     3회      
                           반복

Tool Selection    100%     ✓ PASS    3개 도구
Accuracy          (1.0)               (퀴즈/약점
                                      /복습)

Tool Execution    100%     ✓ PASS    도구 결과
Success           (1.0)     반환      정상 생성

Grounded Rate     66.7%    ✓ PASS    3개 학습
(RAG 활용)        (0.667)             질문 중
                                      2개 검색
```

#### 오른쪽 상단 — 지표별 해석 박스

```
결과 해석

✓ Trajectory 100%
  → Router가 의도를 정확히 파악해 경로 분기 성공

✓ τ 1.0 (완전 일관성)
  → 동일 요청 반복 시 항상 같은 의사결정
  → 멀티에이전트 협력 안정성 입증

✓ Tool Selection/Execution 100%
  → 도구 호출 시점과 대상이 모두 정확

⚠ Grounded Rate 66.7%
  → 66.7%는 정상 범위
  → 33.3% 미검색: 강의자료에서 직접 답변
    가능한 개념 (정답 설계)
```

### 발표 대본 (이 슬라이드 말할 때)

```
"성능평가의 첫 번째 축은 품질 지표입니다. 
14주차에서 배운 Agentic AI 평가방법론을 그대로 적용했습니다.

첫째, 라우팅 정확도는 100%입니다. 사용자의 의도가 학습인지, 잡담인지, 
도구 요청인지, 직답 요청인지를 Router가 항상 정확히 구분합니다.

둘째, 일관성 확률 τ는 1.0입니다. 이는 'LoRA가 뭐야?'라고 5번 반복해도 
항상 learn 경로로 가서 소크라테스식 질문을 한다는 뜻입니다. 
이 지표가 높다는 건 에이전트가 신뢰할 수 있고 예측 가능하다는 의미입니다.

셋째, 도구 호출도 100% 성공합니다. 
'퀴즈 내줘', '약점 저장해줘', '복습 일정 잡아줘'라는 요청이

마지막으로 근거 기반 응답률은 66.7%입니다. 
이게 낮아 보일 수 있지만, 실은 설계 의도입니다. 
일부 개념은 강의자료만으로도 충분히 답할 수 있으니 
검색을 안 하는 거거든요. 
따라서 이 지표가 우수합니다."
```

## 슬라이드 3: 성능평가 B — 시스템 지표

### 제목 영역

```
성능평가 B: 시스템 지표
```

### 부제

```
안정성·성능·재현성 측정 결과
```

---

### 슬라이드 본문 구성

#### 왼쪽 상단 — 시스템 지표 정의 박스

```
측정 항목 정의

▌ 종료 안정성 (Termination Rate)
  모든 API 호출이 타임아웃 없이 
  정상적으로 응답을 반환하는 비율

▌ 응답 시간 (Latency)
  사용자 입력부터 최종 응답까지의 
  전 엔드투엔드 시간

▌ P95 응답시간
  상위 5%를 제외한 95%의 요청이 
  이 시간 이내에 처리되는 수준

▌ 도구 활용률 (Tool Execution Rate)
  tools 경로로 진입한 요청 중 
  실제로 도구 결과를 반환하는 비율
```

#### 중앙 오른쪽 — 시스템 지표 결과표

```
지표                  측정값        기준      결과
────────────────────────────────────────────────
종료 안정성          100% (1.0)    >95%    ✓ PASS

도구 활용률          100% (1.0)    >90%    ✓ PASS

평균 응답시간        8.0 초        <15초   ✓ PASS

P95 응답시간         15.2 초       <20초   ✓ PASS

스트리밍 진행       SSE 실시간      필수    ✓ PASS
표시                모니터링 확인    기능
```

#### 하단 — 성능 분석 (수평 막대)

```
응답 시간 분포 (n=23 샘플)

도구 요청           ████ (3.7초)      짧음
─────────────────────────────────────
잡담 요청           ████ (2.8초)      짧음
─────────────────────────────────────
학습 요청(학습)    ████████████████ (24초) 김
─────────────────────────────────────
직답 요청(escape)  ███████████ (11.4초)  중
─────────────────────────────────────

→ 학습 경로(learn)가 RAG+소크라테스 
  처리 때문에 자연스레 시간 증가
→ 이는 품질과의 trade-off로 허용 범위
```

#### 오른쪽 하단 — 한 줄 결론 박스

```
결론: 시스템 안정성 입증

✓ 100% 종료율: 프로덕션 배포 가능
✓ 8초 평균 응답: 사용자 체감 UX 양호
✓ P95 15초 이내: 극단적 장시간 요청 제외 
  대부분 빠른 응답
✓ 도구 성공률 100%: 
  부가기능(퀴즈·복습) 신뢰도 높음
```

```
첫째, 종료 안정성은 100%입니다. 
23개 요청이 모두 타임아웃 없이 정상 응답했습니다.

둘째, 평균 응답 시간은 8초입니다. 
요청 종류에 따라 다른데요, 도구 요청은 3.7초로 빠르고,

왜냐하면 RAG 검색, 소크라테스 프롬프트 생성,

'약점 저장해줘'라고 하면 항상 저장이 됩니다.

정리하면, SocrAItes는 기능 구현뿐 아니라
```
